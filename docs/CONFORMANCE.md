# Conformance

The integration tests (`tests/it/`) compare the crate with reference implementations. Each
reference set is generated by a script in `scripts/` and checked in as Rust source, so
`cargo test` needs no Python or R. `.github/workflows/conformance.yml` regenerates the
statsmodels, coreforecast and R sets weekly with the pinned tools and runs the tests on the
fresh vectors. The R set must come out byte for byte the same, since R's arithmetic is fixed
by the image. The Python sets move in the last digit with the machine's BLAS, so for them the
tolerance-based tests decide.

## Known differences

- **R's diffuse prior.** For `d > 0`, R's `arima` approximates the diffuse prior with a variance
  of `kappa = 1e6`. Its log-likelihood then differs from the exact one by about 1e-5 at
  `d = 2`, so the R fits are compared with a slack of 5e-5 when the model differences.
- **R's STL.** R's `stl` smooths the seasonal part with degree 0 by default and takes another
  low-pass window, so `stl` and `mstl` follow statsmodels and are not compared with R.
- **`ndiffs`.** It uses R's KPSS lag, `trunc(3 sqrt(n) / 13)`. pmdarima uses
  `trunc(4 (n / 100)^(1/4))` and so picks another `d` on two of its eight series; the crate
  matches R on all of them.
- **statsmodels' `MSTL(lmbda=0)`** skips the transform, because `0` is false in Python. The
  `lambda = 0` reference is `MSTL(log(y))`.
- **coreforecast's STL** smooths the seasonal part with degree 0. Seasonal strengths near the
  threshold of `find_period` can therefore differ.
- **R's ETS intervals without a trend.** `forecast:::class1` sets the third state of `G` to
  `gamma`. That is the first seasonal state only when the model has a slope; for ETS(A,N,A)
  it is the second, so R adds `gamma^2` at horizons `j = m - 1 (mod m)` instead of
  `j = 0 (mod m)`. R's class-2 intervals (multiplicative error, additive season) reuse those
  weights, so ETS(M,N,A) inherits it. The crate uses the correct horizon, checked by
  simulation in `tests/it/ets.rs`, and compares only the means of those models with R.
- **R's class-3 ETS forecasts with a damped trend.** `forecast:::class3` builds
  `F_1 = [[1, 1], [0, phi]]`, `G_1 = [[alpha, alpha], [beta, beta]]` and the weights `(1, 1)`.
  The damped model updates the level from `l + phi b`, which needs `[[1, phi], [0, phi]]`,
  `[[alpha, alpha phi], [beta, beta phi]]` and `(1, phi)`, so R's ETS(M,Ad,M) means and
  variances are off (already at horizon 1, R's mean is `(l + b) s` instead of
  `(l + phi b) s`). The crate uses the damped blocks, checked by simulation, and agrees with
  R where `phi = 1`.
- **R's ETS likelihood** drops the constants `n (ln(2 pi) + 1 - ln n) / 2`; the crate reports
  the full Gaussian log-likelihood, as for ARIMA. R estimates the initial states with the
  smoothing parameters by Nelder–Mead; the crate solves them by least squares at each step,
  which reaches the same or a higher likelihood on every reference model.
- **R's `thetaf` divides by its multiplicative seasonal indices** once its seasonality test
  passes, however small they are. Where an index is below 1e-4 in absolute value (the season
  of a series whose seasonal means are near zero), the crate fits without a season instead
  of dividing by it, so its indices, drift and forecasts differ from R's there. Neither
  reference series reaches it.
- **R's Theta intervals** are `sigma sqrt(1 + (h - 1) alpha^2)` on the deseasonalised scale; `thetaf`
  does not multiply them by the seasonal index as it does the means. The crate follows R.
- **tseries' GARCH optimiser** often stops short of the maximum: on the reference series
  `MODERATE` it returns `beta = 5.5e-15` with log-likelihood -1180.0, where the optimum is
  -1168.8. The crate's fit is checked against the polished optimum, and against tseries'
  likelihood function itself. tseries starts the variance of its likelihood at the mean
  square of the series, but that of its fitted values at the long-run variance
  `omega / (1 - alpha - beta)`; `GarchFit::variances` follows the likelihood.
- **R's `fourier`** starts at `t = 1` and statsmodels' `Fourier` at `t = 0`; `fourier_row` takes
  the origin as an argument.
